# Telegram: вход работает, сообщения не приходят

## Результат проверки

На локальном сервере API Telegram ответило `401 Unauthorized` на `getMe` и `getWebhookInfo`. Это отказ авторизации серверного токена, а не запрет уведомлений браузера. Локальный приём команд бота также выключен (`TELEGRAM_BOT_POLLING` по умолчанию false в development). В базе найден один Telegram-вход без сохранённого чата. Секреты, идентификаторы пользователей и чатов не выводились.

Успешный вход через Telegram на опубликованном сайте не доказывает работоспособность локальной отправки: вход проверяет подпись, а доставка обращается к API бота с серверным токеном. Состояние производственной конфигурации в этой проверке не подтверждалось.

## Исправления

- Обычный `/start` после Telegram-входа сохраняет `telegramChatId`, снимает блокировку и включает сообщения. Раньше сохранялись только флаги. Существующая явная привязка имеет приоритет при выборе владельца чата.
- Одноразовая ссылка Start сохраняет прежнюю защиту: случайный код, срок действия 15 минут, атомарное погашение.
- Сервер больше не предлагает неработающую привязку, если приём команд выключен. Ошибка содержит понятную причину.
- В настройках есть отдельная кнопка **«Проверить сообщения Telegram»**. Браузерные push не нужны для этой проверки.
- Результат различает отклонённый токен, отсутствие чата, блокировку, выключенные сообщения и отказ доставки.
- Браузерная проверка кнопки показала корректное сообщение об ошибке 401; реальное Telegram-сообщение не отправлено.
- Попутно устранены найденные ошибки браузерных push: старый worker, ожидание активации, устаревший ключ и ложный статус подписки без записи на сервере.

## Что требуется для реальной доставки

1. Действующий `TELEGRAM_BOT_TOKEN` из BotFather **для того же бота**, который используется при входе. Записать его в `.env` соответствующего сервера, не в чат. Не создавать новый бот без обновления конфигурации входа.
2. Перезапустить API. Для приёма Start нужен один экземпляр polling: на production он включён по умолчанию, локально включается явно через `TELEGRAM_BOT_POLLING=true`. Не запускать два получателя одного бота одновременно.
3. В профиле открыть «Telegram и уведомления» → «Привязать свой Telegram» → Start. Затем нажать отдельную проверку Telegram.

Действующий токен не подбирался и настройки Telegram пользователя не менялись. Предыдущее решение оставить привязку подготовленной соблюдено: без рабочей конфигурации реальная отправка не заявляется исправленной.

## Проверки

- 66/66 тестов проекта прошли. Новые тесты проверяют обычный Start, ошибку 401, выключенный получатель и восстановление browser push. В тестах Telegram API подменено, сообщений внешним пользователям нет.
- Сборки shared/API/web, проверка типов web и целевой ESLint прошли. Есть предупреждение Fast Refresh, ошибок нет.
- Локальный веб-сервер перезапущен после зависания; web/API health снова возвращают 200.
- `scripts/check-telegram.ts` повторяет диагностику без раскрытия токена.
- Снимок: `qa-telegram-diagnostics-2026-10-18.jpg`.

Механизм привязки соответствует [официальной документации Telegram](https://core.telegram.org/bots/features#deep-linking). Обработка worker учитывает, что [getRegistration ищет регистрацию для URL клиента](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/getRegistration), а не проверяет равенство scope.
