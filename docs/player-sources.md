# Прямые источники AnimeShadow

Плеер использует HLS от AniLibria, прямой MP4 из открытого API AnimeVost и дополнительные JSON API, перечисленные
в `WATCH_DIRECT_PROVIDERS`. [Потоки Kodik](kodik-direct-links.md) разрешаются
по выбранной серии и озвучке сервером и воспроизводятся тем же плеером.
API просмотра возвращает прямое видео (HLS/MP4). По умолчанию используется
собственный плеер. В существующем переключателе доступен только внешний Kodik;
при переключении сохраняются выбранная серия и позиция просмотра. Alloha
не встраивается отдельным iframe.

Alloha подключена через адреса её API. Если Kodik не нашёл тайтл и идентификатора
Кинопоиска ещё нет, используется независимый поиск по точному названию, году и
формату; несовпадающие сезоны и неоднозначные результаты пропускаются. Сервер читает список серий
активного сезона и получает HLS строго для выбранной серии и озвучки. Данные
страницы разбираются без исполнения JavaScript провайдера. Краткоживущие ссылки
и параметры сессии остаются в памяти. Вложенные плейлисты, ключи и видеосегменты
выдаются через собственные адреса сайта с нужными CDN заголовками — это позволяет
использовать тот же интерфейс и нативный HLS Safari. Разрешены только известные
зеркала Alloha и HTTPS CDN `*.vkvideo.cloud`; произвольные URL не принимаются.
Этот источник расходует трафик API-сервера: сегменты передаются потоком,
без сохранения на диск. Kodik имеет приоритет перед Alloha при равной доступности;
неисправный источник обрабатывается обычным механизмом смены источников.

AnimeVost подключён без ключа: POST `https://api.animevost.org/v1/search`
(`name`), затем POST `/v1/playlist` (`id`). У API нет MAL ID, поэтому адаптер
принимает только однозначное точное совпадение названия, года и формата.
Неоднозначные сезоны пропускаются. Проверяется реальный ответ видеосервера;
недоступные HD-ссылки из API не выдаются за рабочее качество. Адреса видео
ограничены проверенным CDN `video.animetop.info`. Кеш — 15 минут; резервный
источник не задерживает рабочий основной более чем на 500 мс.

Страница заранее монтирует собственный плеер без автозапуска. hls.js загружает
буфер около 5 секунд и останавливает загрузку на ближайшей границе сегмента;
первое нажатие запускает уже подготовленное видео и снимает ограничение.
Safari с нативным HLS и прогрессивный MP4 используют `preload=metadata`:
браузер сам определяет объём предзагрузки, точные пять секунд там не обещаются.

Новые серии проверяет `EpisodeAvailabilityService`, каждые 5 минут, пакетами
до 100 отслеживаемых тайтлов с продолжением со следующего пакета. Сначала
обновляется список потоков сайта, затем проверяется реальный плейлист/MP4
новой серии. Дата эфира и плановое число серий не вызывают уведомления.
Первая проверка задаёт исходную точку, а не рассылает старые серии.
Удаление уведомлений: `DELETE /api/me/notifications/:id` или
`DELETE /api/me/notifications` для собственной истории. Все запросы требуют
авторизации и ограничены текущим пользователем.

Проверенные ограничения дополнительных готовых API: Anime365 отдаёт каталог,
но `/api/translations/embed/:id` возвращает ошибку 403 без аккаунта с подпиской;
он не подключён. SovetRomantica API при проверке недоступен. AllAnime возвращает
`AA_CRYPTO_MISSING` на запрос эпизода; его каталог не считается доступным видео.
Внешний резерв встраивается с ограничениями iframe без разрешения всплывающих
окон и навигации верхней страницы. Собственные реклама и интерфейс провайдера
могут присутствовать; рекламные скрипты и VAST в основной плеер не добавляются.
Рекламные сцены, уже включённые в сам видеофайл провайдера, не удаляются.

MP4 выдаётся через `/api/anime/:id/streams/animevost/:releaseId/:episode/video.mp4`:
HTTPS CDN не предоставляет нужный CORS для нашего canvas. Маршрут проверяет
тайтл и серию, принимает только сохранённый источник, ограничивает Range-части
двумя МБ, прерывает upstream при закрытии клиента и не сохраняет файлы на диск.
В отличие от HLS со ссылками на CDN, этот резерв расходует трафик API-сервера.

Регистрация временно создаёт сессию сразу, без кода:
`EMAIL_VERIFICATION_REQUIRED=false` (также значение по умолчанию).
Непроверенная почта не отмечается подтверждённой в базе. Для возврата к коду
установите `EMAIL_VERIFICATION_REQUIRED=true`; для ручного подтверждения в
профиле дополнительно `VITE_EMAIL_VERIFICATION_REQUIRED=true` и пересоберите web.

Для каждого дополнительного провайдера задайте уникальный `id`, HTTPS
`urlTemplate` с `{malId}`, список `streamHosts` и, при необходимости,
`tokenEnv` — имя переменной с Bearer-токеном API. Можно подключить до десяти
провайдеров: запросы выполняются одновременно, каждый ограничен пятью секундами.

Пример ответа провайдера для `/anime/1` (адреса условные):

```json
{
  "malId": 1,
  "expiresAt": "2027-01-01T00:00:00Z",
  "sources": [
    {
      "id": "studio-a",
      "title": "Студия A",
      "kind": "voice",
      "format": "hls",
      "hlsEpisodes": {
        "1": "https://cdn.example.com/title/1/master.m3u8",
        "2": "https://cdn.example.com/title/2/master.m3u8"
      },
      "quality": "1080p",
      "episodesCount": 2
    }
  ]
}
```

`expiresAt` необязателен. Подписанные ссылки хранятся в памяти не дольше
минуты и никогда не записываются в трёхдневный кэш БД. Ответ с истекающими
менее чем через 30 секунд ссылками не используется. Серверный токен API
не передаётся браузеру. Сам поток, вложенные плейлисты, сегменты, ключи и
субтитры должны быть доступны браузеру по HTTPS с корректным CORS.
Все адреса `hlsEpisodes` и `hlsVariants` должны принадлежать `streamHosts`.

Для адаптивного качества, аудиодорожек и субтитров предпочтителен исходный
master playlist: плеер читает его дорожки самостоятельно. `hlsVariants`
нужен только для API с отдельным плейлистом каждого качества:
`{ "1": { "480": "https://cdn.example.com/480.m3u8", "720": "https://cdn.example.com/720.m3u8" } }`.

Пункты «Аудиодорожка» и «Субтитры» появляются в существующих настройках
только при наличии выбора. На Safari используются нативные дорожки,
в остальных поддерживаемых браузерах — полная, лениво загружаемая hls.js.
Документация: [audioTracks](https://hlsjs.video-dev.org/api-docs/hls.js.hls.audiotracks),
[subtitleTracks](https://hlsjs.video-dev.org/api-docs/hls.js.hls.subtitletracks).

При смене источника внутри собственного плеера сохраняется текущая позиция.
«Повторить» обновляет список источников и перезапускает поток с этого места.
Серия без URL не заменяется первой серией. Альтернативные хосты с одинаковым
названием студии остаются доступны отдельно. Клавиши гарнитуры и системная
панель телефона управляют активным видео через Media Session API.

Для расширения каталога: `pnpm catalog:expand`. Цель задаётся
`BULK_SEED_TARGET` (по умолчанию 15000). Для точной цели независимо от `.env`:
`pnpm catalog:expand --target=15000`. Общий каталог показывает все карточки;
фильтр «Только доступные к просмотру» оставляет карточки с плеером. Количество карточек и количество
тайтлов с доступным видео — разные показатели; импорт метаданных не создаёт
отсутствующие видеопотоки. Проверки плеера: `pnpm test:player`,
`pnpm --filter @animeshadow/web typecheck`, `pnpm --filter @animeshadow/api typecheck`.

Импорт читает Shikimori, затем [Jikan](https://docs.api.jikan.moe/), если цель
ещё не достигнута. Дубли объединяются по MAL ID. Уже существующие карточки
сохраняются; новые добавляются небольшими пакетами. Прогресс находится в
`packages/db/.catalog-import.json`. Повтор команды продолжает с сохранённой
страницы; сетевые ошибки не пропускают страницы. Неполный импорт завершает
команду с кодом 2 и фактическим числом карточек. Запускайте один импорт за раз.

## Скачивание серий для PRO

Кнопка «Скачать серию» видна гостям и участникам, включая мобильный плеер.
Гость видит предложение пробного PRO; длительность берётся из общего PROMO.
Фактический доступ проверяется сервером и при выдаче ссылки, и при скачивании.
Выбираются текущая озвучка, серия и ближайшее доступное исходное качество.

`POST /api/anime/:id/download` принимает идентификатор сохранённого источника,
а не произвольный URL. Возвращает ссылку и `statusUrl`. Клиент опрашивает статус
каждые три секунды: сначала сервер полностью собирает MP4 во временный файл,
затем отдаёт его с точным Content-Length и поддержкой Range (докачка).
Ошибка источника показывается до начала скачивания. Повтор кнопки после сетевой
ошибки продолжает подготовку той же серии, не запускает второй конвертер.

Доступны HLS, Kodik, Alloha и MP4. Перенаправления Kodik разрешены только внутри
того же CDN (исходный хост, его поддомены и проверенные узлы solodcdn.com, включая
p14 → p13), до четырёх переходов; адреса внутренней
сети запрещены. Относительные пути считаются от конечного адреса плейлиста.
Короткие сетевые сбои повторяются до трёх раз, включая обрывы тела ответа.
Фрагмент проверяется целиком перед передачей конвертеру. До трёх следующих
фрагментов по 4 МБ подгружаются параллельно, без кэширования всей серии в памяти.
Начальный запрос FFmpeg bytes=0-
не передаётся в шлюз Alloha, который принимает только ограниченные диапазоны.

До двух подготовок на процесс API и одна на пользователя, до 20 минут каждая.
Размер файла ограничен 4 ГБ и доступным местом с резервом 512 МБ; перед выдачей
проверяется завершение конвертера и отсутствие потерянных фрагментов. Готовый
файл доступен 30 минут; сервер удаляет его по истечении срока и при штатной
остановке. После аварийного завершения очисткой системного временного каталога
управляет ОС (на проде сервис использует PrivateTmp).

Проверяется рабочий FFMPEG_PATH, затем системный ffmpeg и резерв ffmpeg-static
(на Windows встроенный конвертер используется первым). Команда deploy устанавливает
системный ffmpeg. Проверка: pnpm test:download — полный тестовый MP4, Alloha,
PRO, потерянный фрагмент и докачка; tests/download-redirects.test.ts — переходы CDN.

Ручная проверка реального полного эпизода: `scripts/check-episode-download.ts`.
Она допускает только локальный API, не создаёт аккаунты и не меняет их права;
источники получает через обычные публичные маршруты. `QA_ANIME_ID`, `QA_SOURCE_ID`
и `QA_EPISODE` задают тайтл, источник Kodik/Alloha и серию. Проверяются готовый MP4,
полная передача байтов, SHA-256 и докачка. Файл после проверки удаляется.

## Музыка и фон

Опенинги берутся из AnimeThemes по точному MAL ID и показываются после проверки
медиа. Отдельный аудиоплеер сохраняется между переходами по сайту. Неудавшийся
формат получает одну резервную попытку; недоступная композиция скрывается.

Фон использует локальные изображения NASA и небольшие CSS-анимации лепестков;
полноэкранной перерисовки нет. На телефоне до шести лепестков, на слабых устройствах
до четырёх. При просмотре видео, скрытой вкладке или уменьшении движения анимация
останавливается. Источники изображений и лицензия анимации: `apps/web/public/background/NOTICE.txt`.
